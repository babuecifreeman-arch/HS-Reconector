HEARTHSTONE RECONNECTOR 4.2 — WINDOWS 11

ЗАПУСК И ПЕРВОЕ ОБУЧЕНИЕ
1. Закройте старую версию через трей и распакуйте этот архив в отдельную папку.
2. Запустите HearthstoneReconnector.exe с подтверждением прав администратора.
3. По возможности запускайте приложение ДО входа в матч: раз в секунду оно
   наблюдает за установленными TCP-соединениями Hearthstone и отмечает новые.
4. Во время боя нажмите кнопку с котиком. Если соединение определено по журналу,
   приложение выберет его автоматически. Иначе откроется список для ручного выбора.
   Также список доступен в трее: «Выбрать соединение вручную…».
   Выбирайте адрес матча по игровому журналу. «Новое» и «знакомый порт» — подсказки,
   они сами по себе не доказывают, что подключение относится к матчу.
5. Если найден новый TCP-сокет и свежая запись SERVER_GAME_STARTED, адрес
   сохраняется автоматически. Если TCP заменён, но журнала недостаточно, после
   фактического возвращения в матч выберите в трее «Матч восстановился — запомнить».
   Этот пункт доступен 90 секунд после результата SOCKET_REPLACED.
   Ошибка или истечение ожидания не обучают приложение. Ручной выбор сам по себе тоже.

КАК РАБОТАЕТ ВЫБОР
Сначала проверяется адрес из актуального для процесса игрового журнала.
Далее проверяются подтверждённые адреса: точное совпадение IP и серверного порта,
единственность кандидата и появление нового сокета после начала наблюдения.
При отсутствии подходящей записи остаётся прежний выбор единственного порта 3724.
При неоднозначности приложение показывает список; в нём нет предвыбранной строки.
Один выбор приводит к разрыву ОДНОГО конкретного TCP-соединения.
Автоматического последовательного отключения кандидатов нет.

Для двух соединений на 1119 (как в присланном логе) без журнальных данных или
подтверждённой памяти нужен ручной выбор. Один лишь порт 1119 не выбирает адрес.
Память не закрепляет локальный порт — он может меняться при каждом подключении.
При новом серверном IP, нескольких подходящих сокетах либо запуске приложения
уже в матче может снова понадобиться ручной выбор. Это не универсальный автоопределитель.
Записи хранятся 30 дней, отдельно для каждого пути установки игры; максимум 128 записей.
Сброс: трей → «Сбросить память соединений».
Файл: %LOCALAPPDATA%\HearthstoneReconnector\connections-v1.txt

МЕХАНИЗМ И ДИАГНОСТИКА
Используется SetTcpEntry для точечного закрытия установленного IPv4 TCP-соединения.
Помощник повторно проверяет процесс, время его запуска и полный адрес выбранного
сокета (локальные и удалённые IP и порты). Исчезнувший сокет не заменяется другим.
До 12 секунд проверяются исчезновение старого сокета и появление нового на прежний
сервер. Зелёные царапины: TCP и новый SERVER_GAME_STARTED подтверждены;
жёлтые: результат не подтверждён по журналу или ожидание отменено; красные: ошибка.
Нужный журнал ищется в Logs рядом с Hearthstone.exe, включая вложенные сессии.
Предпочитается самый свежий подходящий файл; журналы до запуска процесса пропускаются.
Повторное нажатие недоступно до завершения операции и ещё 12 секунд после неё.

Трей → «Открыть журнал». В reconnectоr.log записываются:
CANDIDATE (new/known), SELECT (GAME_LOG, MEMORY_EXACT_ENDPOINT,
MEMORY_NETWORK_AND_PORT, KNOWN_PORT_AND_UNIQUE_NEW_SOCKET, UNIQUE_3724, MANUAL),
DIRECT_BEGIN, SET_TCP_ENTRY, OLD_SOCKET_GONE, MATCH_RESTORED и MEMORY_CONFIRMED.
Для диагностики смены адреса каждый запуск имеет поле attempt. RECONNECT_BASELINE
и RECONNECT_TARGET фиксируют исходные сокеты и выбор; SOCKET_REMOVED/SOCKET_ADDED —
полный локальный и удалённый адрес, время появления и отношение к выбранному сокету:
SAME_REMOTE_ENDPOINT, SAME_HOST_NEW_REMOTE_PORT, NEW_HOST_SAME_REMOTE_PORT либо
NEW_HOST_AND_REMOTE_PORT. GAME_LOG_CAPTURE/GAME_LOG_DELTA показывают выбранный файл,
число новых байтов, свежий endpoint и SERVER_GAME_STARTED. RECONNECT_TIMEOUT содержит
итоговые признаки и снимок всех оставшихся сокетов. Строки одного опыта сопоставляются
по одинаковому attempt; журнал не содержит содержимое игровых сообщений.
Все данные локальные, приложение ничего не отправляет на внешние сервисы.

ИНТЕРФЕЙС
Кнопка с прозрачным фоном снаружи золотой рамки, ховером и эффектом нажатия.
При реконнекте лапки царапают по очереди, царапины пульсируют цветом состояния.
В трее «Показать / переместить кнопку» включает пунктирную рамку и стрелки.
Перетащите кнопку левой кнопкой мыши; повторный выбор пункта сохраняет положение.
В трее также есть сброс положения, журнал и выход.

ОГРАНИЧЕНИЯ
IPv6-разрыв не поддерживается: приложение отменит операцию и покажет сообщение.
Нужны Windows 11, .NET Framework 4.x и права администратора.
Разрыв TCP не гарантирует возврата в матч или отсутствия вылетов игрового клиента.
Ручной выбор служебного соединения может нарушить авторизацию и привести к выходу.
В эксклюзивном полноэкранном режиме оверлей может не отображаться: используйте оконный.
Новые правила брандмауэра не создаются. При запуске удаляются старые правила HSRC2.
RestoreConnection.cmd оставлен для очистки этих правил прошлых версий.

ПРОВЕРКИ
Проверены сценарий из лога друга, сохранение/загрузка подтверждённой памяти,
отказ от выбора только по порту, смена локального порта, несколько одинаковых
адресов, перезапуск процесса, разные установки, срок памяти и повреждённые строки,
ручной выбор без предвыбранного кандидата, актуальность журнала, UTF-8 обмен,
подтверждение только по новым строкам, прозрачность, анимация, клики и перемещение.
Чтение реальной TCP-таблицы ограничено sandbox (Access denied); настоящий разрыв
и живой матч на компьютере друга в этой сборке не проверены.
